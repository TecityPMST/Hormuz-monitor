# Iran–Hormuz War & US Economic Shock Monitor — HTML Dashboard

A static, single-page dashboard that mirrors the daily PDF edition **in full**
— all 9 numbered sections, in the same order, with the same tables and
complete narrative text (headline judgment, live tape, bond-yield analysis,
shock-score grid, what's changed, scenario map, watchlist, source log,
protocol, methodology). It is not a condensed summary. Beyond the PDF
content it adds: a toggle to switch the whole page between the latest and
previous edition, a "Score history" trend chart, and a full downloadable
archive table covering every PDF in the folder.

Designed to be pushed to a GitHub repo and served via **GitHub Pages** (or
any static host) — no server, no build step at request time, no external
runtime dependencies (Chart.js is vendored locally in `vendor/`).

## What's in this folder

| File | Purpose |
|---|---|
| `index.html` | The generated dashboard. This is the file GitHub Pages serves. **Do not hand-edit** — regenerate it with `build_dashboard.py`. |
| `build_dashboard.py` | Reads all the JSON data files below and writes `index.html`, with everything embedded inline as JS (per your "embed in HTML" choice) rather than fetched at runtime. |
| `generate_editions.py` | Source-of-truth script that builds `editions.json`. Holds the FULL text/tables of each edition as Python literals, copied verbatim from that edition's PDF build script. Edit this file, not `editions.json` directly. |
| `editions.json` | Generated by `generate_editions.py`. Full section-by-section detail for the **two most recent editions** (the ones the toggle switches between). Keyed by ISO date. |
| `update_score_history.py` | Regenerates `score_history.json` by reading **every PDF in `pdf/`** with `pdftotext` and extracting that edition's actual score straight out of its headline sentence — never hand-typed. Feeds both the trend chart and the score column in the full archive table. **It MERGES rather than replaces** — see the cloud-sync warning below. |
| `score_history.json` | Generated by `update_score_history.py`. `{date, score, driver}` per edition, 12 Jun 2026 onward (the first archived PDF). |
| `update_gas_series.py` | Regenerates `gas_series.json` by reading **`US Iran BBG Data.xlsx`** directly — the same file and the same robust column-scanning parser (ticker labels auto-detected, not hardcoded column indices) the daily PDF build uses. Takes the spreadsheet path as an argument. |
| `gas_series.json` | Generated by `update_gas_series.py`. AAA (AUTMUSAG) / DOE (USRFRUSA) closes, 2026-01-01 onward, for the gasoline chart. |
| `update_pdf_manifest.py` | Regenerates `pdf_manifest.json` by scanning **every file in `pdf/`**. Drives the "Full PDF editions" table so every PDF you've saved gets a row and a download link — not just the two kept in full detail. |
| `pdf_manifest.json` | Generated by `update_pdf_manifest.py`. `{date, filename, label}` per PDF in `pdf/`, newest first. |
| `logo.png` | Tecity logo, inlined as base64 into `index.html` at build time. |
| `vendor/chart.umd.min.js` | Chart.js v4.4.4, vendored locally (via `npm pack chart.js@4.4.4`) so the page has no CDN dependency. |
| `pdf/*.pdf` | Every archived edition PDF. All of them ship and all are downloadable, but the "Full PDF editions" table lists only the newest `ARCHIVE_LIMIT` (currently 7) — see the cap section below. Only the two most recent are also fully detailed via `editions.json`. |
| `../index_preview.html` | A copy of `index.html` one level up, for double-clicking without a local server. Identical content; its only difference is that the Chart.js `<script src>` is rewritten to `hormuz_dashboard/dashboard/vendor/chart.umd.min.js` so the relative path resolves from where the file sits. Regenerate it whenever `index.html` changes. |

## How the three data feeds tie to your source files

This was the point of the latest revision — nothing in the dashboard is a
one-off hand-typed snapshot; each of the three data-driven panels reads from
the file you actually keep:

1. **"US retail gasoline" chart** → `update_gas_series.py "US Iran BBG Data.xlsx"`.
   Reads the spreadsheet fresh every run using the same header-row auto-scan
   the PDF build's parser uses (see `HORMUZ_MONITOR_INSTRUCTIONS.md` §3), so
   a relabelled ticker or inserted column doesn't silently break it.
2. **"Score history" chart + the archive table's Score column** →
   `update_score_history.py`. Opens every `pdf/*.pdf`, runs `pdftotext`, and
   regexes out that edition's own "Score HOLDS/FALLS/RISES/... at N/30"
   sentence — the number is never re-typed by hand, and the driver text
   shown in the chart tooltip is that edition's actual sentence.
3. **"Full PDF editions" table** → `update_pdf_manifest.py`. Lists every file
   in `pdf/`, so adding or removing a PDF from that folder is the only thing
   that changes what's downloadable — no separate list to maintain.

### The archive table is capped at 7 rows (set 20 Aug 2026)

`build_dashboard.py` defines **`ARCHIVE_LIMIT = 7`** near the top. The table
renders only the newest N entries of `PDF_MANIFEST`, newest first.

This is a **display cap only**. Nothing is deleted and nothing is withheld:

- `pdf/` still holds **every** archived PDF and they all still ship.
- `pdf_manifest.json` is still a full scan of the folder — do not trim it.
- The **score-history chart is unaffected** and still plots the whole run
  from 12 Jun 2026. That is deliberate: the trajectory is the point of that
  chart, and capping it would destroy the one panel that shows the war in
  full.
- Older editions stay reachable by direct URL (`pdf/<filename>`); they are
  simply not listed.

The table's intro note is generated at runtime and states both numbers
("the 7 most recent … 43 editions are archived in total"), so the page never
implies the archive is smaller than it is.

**To change it:** edit the one constant and rerun `build_dashboard.py`. Set
`ARCHIVE_LIMIT = None` to list every edition again.

If you ever do want the folder itself pruned rather than the table capped,
note that `update_score_history.py` **merges** and never drops a stored
entry, so deleting old PDFs would shrink the table and the repo without
harming the trend chart — but those editions would stop being downloadable
from the page.

### ⚠️ Cloud-sync warning (learned 17 Aug 2026)

This folder is inside OneDrive. A PDF that has been evicted to a **cloud-only
placeholder** still appears in a directory listing but **cannot be opened** —
`pdftotext` fails on it. On 17 Aug a full rebuild of `score_history.json` in
that state silently dropped the archive from **39 editions to 4**, because
every PDF older than about a week was a placeholder.

`update_score_history.py` now **merges** instead of replacing: editions it can
read are re-derived from the PDF and overwrite the stored value; editions it
cannot read keep their previously derived entry, and the script prints a
`NOTE:` listing them. It also refuses to write an empty file. If you ever need
a genuine full rebuild, force OneDrive to download `pdf/` first ("Always keep
on this device") and check the script reports `N re-derived, 0 retained`.

The same applies to `vendor/chart.umd.min.js`. If it is a placeholder, the
build still succeeds (the tag is a reference, not an inline copy) but the
charts will not render until OneDrive hydrates the file.

`editions.json` (the two-edition toggle with full section-by-section detail)
is the one piece that's still hand-maintained via `generate_editions.py`,
because that level of narrative detail only exists in the day's PDF build
script — there's no structured source file to scan it out of.

## Updating for a new edition (do this each day, after the PDF is built)

1. **Add the new edition to `generate_editions.py`.** Copy the newest
   `EDITIONS["..."] = {...}` block and adapt every field for the new date —
   headline, all of section 1's tables (oil/gas, UST, cross-asset, strait),
   section 2's analysis text, the six channels and score-grid rationale,
   what's-changed, scenarios, watchlist, source log, protocol, methodology.
   None of this is new research — it's the same content already written for
   the day's PDF, just copied into the matching field instead of a
   `Paragraph()`/table call. **Delete the oldest date's block** so the file
   defines exactly two editions. Then run:
   ```bash
   python3 generate_editions.py
   ```
2. **Copy the new PDF into `pdf/`.** Keep every old one too — the full
   archive table wants all of them, not just the latest two. Then run:
   ```bash
   python3 update_score_history.py
   python3 update_pdf_manifest.py
   ```
3. **Refresh the gasoline series** against the latest spreadsheet:
   ```bash
   python3 update_gas_series.py "/path/to/US Iran BBG Data.xlsx"
   ```
4. Rebuild the page:
   ```bash
   python3 build_dashboard.py
   ```
5. Refresh the standalone preview copy one level up:
   ```bash
   python3 - <<'PY'
   html = open('index.html', encoding='utf-8').read()
   html = html.replace('<script src="vendor/chart.umd.min.js">',
                       '<script src="hormuz_dashboard/dashboard/vendor/chart.umd.min.js">', 1)
   open('../../index_preview.html', 'w', encoding='utf-8').write(html)
   PY
   ```
6. Commit and push:
   ```bash
   git add index.html editions.json generate_editions.py \
           score_history.json gas_series.json pdf_manifest.json pdf/
   git commit -m "Dashboard: 2026-07-28 edition"
   git push
   ```

## Publishing on GitHub Pages (one-time setup)

1. Create the GitHub repo (you said you'll do this and share the URL).
2. Push this folder's contents to the repo's default branch.
3. In the repo, go to **Settings → Pages**, set **Source** to "Deploy from a
   branch", branch = your default branch, folder = `/ (root)`.
4. GitHub will publish at `https://<your-username>.github.io/<repo-name>/`
   within a minute or two. Every future push to `index.html` updates the
   live page automatically — no rebuild step on GitHub's side.

## Notes on the data

- **Score history** is sourced by reading the actual score sentence out of
  every archived PDF from 12 Jun 2026 onward — it is not reconstructed or
  estimated. Editions before 12 Jun (1–11 Jun) predate the archive and are
  not included. The extraction anchors on the capitalized word "Score" that
  starts each edition's verdict sentence (verb casing varies — FALLS/falls,
  HOLDS/holds, etc. — so that part of the match is case-flexible), which is
  what keeps it from being fooled by incidental lowercase mentions elsewhere
  in the PDF (e.g. "AAA pump — score reference").
- The 25 Jun → 26 Jun dip-and-reversal (18 → 20) is real: two channels were
  downgraded on a 25 Jun intraday low and reverted the next session once the
  confirmed close came in higher. It's left in the history un-smoothed
  because it's a useful illustration of exactly the "confirmed closes only"
  discipline the monitor's methodology insists on.
- Visual language matches the PDF house style: navy `#1f3a5f`, header blue
  `#2c4a6e`, rule grey `#b8c4d2`, amber `#c77f2e` for the DOE gasoline line —
  same palette, adapted to a web layout instead of print pages.
